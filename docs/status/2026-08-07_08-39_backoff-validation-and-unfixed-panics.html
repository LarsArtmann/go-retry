dTotally Fucked Up

Every panic below was reproduced this session against the current source (post-commit d67798a) with runnable programs. All three sit on the retry failure path — a panic here converts a recoverable downstream blip into a process crash.
Panic · B1

Omitting MaxDelay crashes the process

retry.go:137-139 · reproduced

Config.Validate() never checks MaxDelay. An unset (zero) MaxDelay makes min(delay, 0) == 0, so rand.Int64N(int64(0)/2) → Int64N(0) → panic. This is trivially hit: any Config literal that omits MaxDelay — an extremely common mistake. 

// REPRODUCED 2026-08-07: "B1 PANIC: invalid argument to Int64N"
retry.Backoff(retry.Config{
    MaxAttempts:  3,
    InitialDelay: 100_000_000, // 100ms
    Multiplier:   2.0,
    // MaxDelay OMITTED
}, 1)
Panic · B2

Sub-2ns delays pass Validate but panic

retry.go:137-139 · reproduced

InitialDelay: 1 (1 nanosecond) passes Validate() (it only rejects ≤ 0). The computed delay is 1ns; int64(1)/2 == 0 → Int64N(0) → panic. Reachable via Do, Backoff, and ComputeDelay. 

// REPRODUCED 2026-08-07: "B2 PANIC: invalid argument to Int64N"
retry.ComputeDelay(1, 5_000_000_000, 2.0, 1)
Panic · B3

DefaultConfig panics at attempt 38 (math.Pow overflow)

retry.go:132-135 · reproduced

At high attempts, float64(initial) * math.Pow(mult, n) overflows int64. The conversion time.Duration(hugeFloat) wraps to INT64_MIN; min(negative, MaxDelay) keeps the negative; Int64N(negative) → panic. Plain DefaultConfig() (100ms × 2.0) overflows at attempt 38. 

// REPRODUCED 2026-08-07: "B3 PANIC: invalid argument to Int64N"
cfg := retry.DefaultConfig()
cfg.MaxAttempts = 40
retry.Backoff(cfg, 38)
