2. **Filtered pipes never carry verdicts - including drill verification.** The ritual rule says raw `ok`/`FAIL` summaries for tests; drill 3 (d2) proves the same rule applies to mutation-drill output. A drill "pass" that is a build failure proves nothing.
3. **Verify-before-routing applies to decisions, not just tasks.** Before writing a ROADMAP decision, grep for existing artifacts that may already answer it (d3).
4. **Read the options/API surface before calling it.** Two API-name guesses today (`WithOnExhausted`); one `rg options.go` would have prevented both.
5. **Structure new test files for the lint gates upfront** (cognitive complexity, short variable names in tight scopes, `WaitGroup.Go`): the first harness draft needed a refactor pass the linters dictated.
6. **pkg.go.dev verification should gate release done-ness**, not trail it by hours (the 404 sat unverified from 20:0x until 02:10).
7. **The stress harness runs a second DoWithValue loop per iteration** - doubles the cost; fold the value check into the same loop next time it is touched.
8. **Run `buildflow --fix --build-mode=full` as the session-close gate.** Individual gates are green, but the orchestration (including the erraudit step, gvac, dprint via profile) was not re-run after ≈15 new commits.
9. **Re-run `BenchmarkComputeDelay` when the toolchain changes** - FEATURES explicitly asks for it; the toolchain is go1.27.1 and nobody has re-run the benchmark since the doc's ≈20-35 ns/op numbers were recorded.
