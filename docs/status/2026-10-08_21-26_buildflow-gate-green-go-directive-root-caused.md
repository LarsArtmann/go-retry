1. `go-mod-update` (BuildFlow step) — unconditionally bumps the `go` line to the installed toolchain minor. Known from the 2026-10-05 restore commit `09bbfce`.

Both are now dispositioned in committed config, so the flip-flop cannot recur until someone deliberately re-decides the pin policy.

## e) WHAT WE SHOULD IMPROVE

1. **Repair tools must announce what they rewrite.** The costliest detour of this session was discovering that a "structure" linter owns a `go-version` repair rule. A BuildFlow preflight or summary line listing "files rewritten by repairs, per tool" would have collapsed an hour of bisection into seconds. Fleet-level: BuildFlow/go-structure-linter upstream.
2. **Bisect-by-step should be a documented reflex.** The `buildflow -s "<step>" --fix` + check loop identified innocence fast; the missing half was that exonerating all gomod steps was not enough because the writer was not a gomod tool. The watcher-plus-step-log-correlation technique is now in `docs/engineering-notes.md`; it generalizes to any "file flips between runs" bug and belongs in the crush-config lessons file (by commit, cross-project).
3. **Flake-prone assertions need a stress mode somewhere.** Both flakes were invisible at CI's `-count=1` and trivially reproducible at `-count=10`. Either CI should occasionally run a stress job, or flake-prone timing assertions should be written race-proof from the start (both fixes now follow the pattern: assert the formula-derived bound of whichever outcome legitimately happened).
4. **The daemon commits broken intermediate states.** `bc2c99a`/`4ba7838` are fossilized red states. A pre-commit guard (even just the repo's own `go test -run TestModuleGoDirectiveStaysPinned`) inside the daemon loop would prevent fossilizing states the repo's own guard test rejects.
5. **Sentinel declaration typing is a fleet-wide erraudit contract.** The `var X error = ...` pattern (not concrete types) is required for erraudit's sentinel recognition. This is a cross-project Go convention worth capturing in `how-to-golang`/`go-error-modernization` skill references so other repos do not rediscover it via lint findings.
6. **AGENTS.md size pressure is structural.** At 291 lines it exceeded the 220-line preflight by 71; the fix (pointer section + long-form notes file) works, but future gotchas should default into `docs/engineering-notes.md` with one-line AGENTS.md pointers to avoid re-inflating the file.
